# 室外故障的离线代码修复

依据：2026-10-28 室外调试报告，以及当前源码、机载 `stash@{0}` 保存的现场改动。
现场补丁有一部分只保存在暂存记录，并不在当前代码里，不能把报告中的“已部署”当作当前版本已包含。
本次只读查看机载 Git 记录；没有启动定位采集、发送姿态／移动命令或重启机载服务。

## 已修复

### 1. 空旷路面被当成雷达断流，速度被清零

`lynx_navigation.on_scan` 和 `lynx_watchdog.scan` 都要求至少有一个有效的有限距离。
空旷路面全为 `+inf` 时，上层或最终速度守卫就会误判雷达死亡。

两处改为调用同一个 `outdoornav.scan_health.healthy_scan`：新鲜、格式正常的全 `+inf` 扫描算有效；
过期、未来时间、空数组、全 NaN／负无穷／无效距离不刷新健康状态。障碍判定仍交给代价地图。

守卫状态新增 `blocked_reasons`，并经 `/api/status` 的 `command_status` 返回。
`scan_stale`、`command_stale`、`localization_unready` 等原因能直接看出是哪道门在发零速，
不再只有“任务正在行驶”却不知为何没动。断流和指令超时仍输出零速。

### 2. 无回波射线不能清除旧障碍

扫描生成配置原为 `use_inf=true`，障碍层却是 `inf_is_valid=false`。
改为 `inf_is_valid=true`，使当前扫描的无回波方向可以沿射线清除旧标记。
这不代表已验证真实行人绕行，也不代表任何无数据情况都应视为自由空间。

### 3. 短暂缺少定位时解引用空值

任务开始规划、构造路线、执行循环以及到达后复查位置，均通过 `wait_for_ready_pose` 取得有效位置。
缺少／过期位置时先设置停止状态、发布零速，短暂等待恢复；默认最多 5 秒，由
`navigation_recovery_timeout_s` 配置。恢复才继续，持续不可用则结束任务并走既有停车确认流程。
取消、服务关闭、所有权冲突或时钟回退不等待宽限。

这里的宽限只延迟“判任务失败”，**不是允许在没有定位时继续开 5 秒或 30 秒**。

### 4. IMU 启动查询丢失后永不重试

未收到 AXIS6 回复时，每 5 秒重新发送一次原有只读查询；即使没有数据返回也会重试。
运行时长按启动时刻计算，不会因为重试把 `--duration` 的截止时间不断推后。
未确认模式仍保持未确认，不把未知／六轴模式伪装成九轴。

### 5. 生产入口缺少前雷达安装变换

生产启动脚本补上与已有前雷达 primitive／模拟入口相同的 `base_link → airy_201` 安装变换。
桥接、静态变换和导航栈由已有子进程管理器收尾；任一子进程退出时不留下独立速度桥。

### 6. GGA 改正年龄：只对现场演示档放宽

新增 `require_correction_age`，默认 `true`；`robot.fieldtest.json` 显式设为 `false`。
年龄仍显示在诊断中，但该演示档不单独因为 GGA 年龄升高拒绝位置。
仍要求有效解、差分标志、固定／浮点类别、精度估计合格，并保留定位消费者的历元、新鲜度和速度质量检查。

这是一项**演示策略**，不是证明所有过期差分都安全。不能仅凭“仍是固定解”保证改正足够新鲜，
也没有把报告对 1005／1006 消息和 GGA 年龄关系的解释当作已证实的固件根因。

## 没有照搬的改动和仍待验证项

- 没有将 3 m 内的雷达回波全部屏蔽：这会同时屏蔽真实近处障碍。现有扫描下限未扩大；
  自车回波的来源与正确几何过滤仍需使用实测点云确认。
- 没有把膨胀带直接等同于“整片禁行区”。当前规划器 `allow_unknown=true`，全局图也没有静态道路层；
  报告关于“路两侧默认不可走”的描述不能不加核对地套到当前配置上。
- 没有取消航向模式确认、任意放宽跳变门槛，或假装已验证行人绕行。
- 底盘不在导航模式、轮子不响应是实际状态问题，本次不自动起立或操作机器狗来验证。
- 尚未验证这些修复能让实车完成取餐点任务；本次没有实车到达结论。

## 离线验证

在本地 Docker 的 ROS 2 Humble 环境运行，域 94、localhost；使用构造消息和对象，不启动底盘／GNSS／IMU 采集：

```bash
source /opt/ros/humble/setup.bash
export PYTHONPATH="$PWD:$PWD/ros_ws/src/outdoornav_ros:${PYTHONPATH:-}"
export ROS_DOMAIN_ID=94 ROS_LOCALHOST_ONLY=1
python3 -m pytest tests/test_fieldtest_recovery.py tests/test_lynx.py \
  tests/test_rtk_imu.py tests/test_demo_policy.py -q
```

结果：51 项通过。覆盖双消费者全 `+inf` 扫描、断流清零及原因、位姿缺失时停车与恢复／超时／取消、
查询无回复时重试及总时限、生成的障碍层清除配置、演示与严格档的 GGA 年龄策略。

本次提交包含上述代码、离线回归与说明；未部署或重启山猫上的导航服务。
