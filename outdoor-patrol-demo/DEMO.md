# 给导师的三分钟演示稿

提前打开 http://localhost:5173，浏览器最大化。确认地图完整显示，点击“重置巡航”。演示不需要联网、RTK 或机器狗。

## 0:00—0:30：说明目标和地图

> 这是一个面向园区机器狗巡航的二维全局地图原型。目前根据路网图和卫星截图人工辅助标注，目标是先跑通“地图、任务、全局路径、执行展示”的完整流程。
>
> 地图保留建筑、绿化、道路和看不清的地面。暗色部分是高楼阴影，不是水体；阴影本身也不代表障碍。地图比例尺暂用演示值，尚未与 RTK 对齐。

操作：切换一次“通行性地图”，再切回“语义地图”。时间允许时打开图层设置，勾选道路拓扑网络，再关闭设置。

> 彩色区域说明这里是什么，道路网络说明这些位置如何连通。未知区域默认不参与规划，车辆不会直接穿过建筑去找最短直线。

## 0:30—1:00：生成并执行任务

操作：点击右上角“一键演示”，保持默认 5× 播放。

> 任务按顺序访问北侧入口、中央路口、东侧楼前、南侧道路和西侧道路，最后回到起点。任务点需要停留两秒；中间的转弯和道路连接点只需经过。
>
> 路线由道路图上的 A* 计算。此时移动的是模拟执行器，右侧展示当前目标、模拟用时、路程和任务完成情况。

## 1:00—2:30：展示封路重规划

机器狗在中央路口完成停留后，系统会模拟关闭前方的楼前连接道，无需手动操作。

> 现在演示前方道路封闭。这是我们主动设置的事件，不是来自真实传感器。橙色虚线显示上次路线，绿色显示新的绕行路线。
>
> 重规划从当前位置开始，已经完成的任务不会被清空。如果路网完全断开，系统会报告目标不可达，停在当前位置，等待恢复道路后继续。
>
> 这部分的意义是让全局地图能够输出连续路线和关键途经点。后续会与同门的局部导航对接，由它负责真实行走、附近障碍和到点反馈。

等待巡检结束。若演讲节奏较快，可以点 10×；若需要解释地图，随时暂停。

## 2:30—3:00：展示结果与后续路线

操作：任务完成后，点击“导出数据”，下载路线 JSON 或途经点 CSV。

> 这版不仅展示一条动画路线，还能导出地图、完整任务顺序、当前规划路径、已走轨迹和关键途经点。点位区分经过和巡检停留。
>
> 当前导出使用局部的演示米制坐标。下一步先实测校准并对齐 RTK，再和同门确认路径接收和执行反馈接口，之后用激光与视觉语义建图逐步替换人工标注。

## 现场可以追加的互动

- **证明不可达不是假动画**：重置 → 打开封路工具 → 同时封闭“北侧连接道”和“北侧内部道路”，北侧起点将与内部路网断开；恢复其中一条后重新获得路线。关闭道路管理，点击开始即可继续。
- **修改任务**：重置 → 删除或调整巡检点顺序 → 重新生成路线。
- **从道路中间出发**：重置 → 设置起点 → 点道路中间 → 重新生成路线。起点会吸附到道路，不必选在预置节点上。
- **查看图层**：开启道路拓扑网络，说明“道路可通行”和“从当前位置可达”的区别。

## 回答可能的问题

**现在是自动建图吗？**

不是。当前地图由图片人工辅助标注；路径计算、可达性判断和任务模拟已经自动化。

**今天能直接让机器狗走吗？**

还不能。需要校准实际尺度和坐标、确认现场通行条件，并接入机器人定位、局部导航和任务反馈。

**图上距离可靠吗？**

只在当前假设比例尺下自洽，不是实测距离。页面和导出文件都保留了演示标记。

**为什么先用二维地图和道路网络？**

当前任务以地面道路巡航为主，道路网络能快速验证任务连接和全局路线；后续更精细的局部地图负责真实几何、地形和避障。

## 新增：A→B 区域规划演示（约一分钟）

1. 切换到右上方「A→B 规划」。
2. 在东侧竖直道路的亮绿色区域内选 A，再在南侧道路选 B；可选偏离中心线但仍位于亮绿色区域内的位置。
3. 点击「规划 A→B」。指出起终点保持原位置，路径在有宽度的区域内规划。
4. 展示右侧 K 点列表：起终点、转弯、路口和间隔引导点。说明简化关键点后仍需检查连线是否穿越障碍。
5. 点击播放预览，下载路线 JSON 或重要途经点 CSV。输出同时保留完整路径，坐标仍未对齐 RTK。
6. 可选：在封路管理中关闭 A 所在路段；旧路线立即失效，重新规划提示选点不可通行。恢复道路再规划即可。

不要把绿色区域解释为已经现场测量的自由空间。它来自当前人工道路标注和假设宽度。真实部署要用实测几何与实时感知替换这份通行模型。
