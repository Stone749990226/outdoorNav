# 巡境 · 园区二维地图与巡航规划 Demo

一个可以直接在本地浏览器演示的中文应用：语义地图、通行性与可达性、A→B 区域规划、重要途经点提取、道路 A*、多点巡航、模拟封路重规划，以及地图和路线导出。

**底图根据用户提供的园区截图重绘；图中的暗色区域是建筑投影，不是水体。道路通行性、地面尺度均未现场校准。没有连接真实机器狗、RTK 或 ROS。**

## 直接运行

需要 Node.js 22.12 或更新版本。从仓库根目录执行：

```bash
cd outdoor-patrol-demo
npm ci
npm run dev
```

打开终端给出的地址，通常为 **http://localhost:5173**。点击右上角 **一键演示**，无需准备图片或编辑代码。

安装后应用不请求在线地图、字体或其他在线资源，可离线运行。

生产构建及预览：

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`。预览地址通常为 http://localhost:4173。不要直接双击 HTML 文件，应使用上述 HTTP 服务。

## 如何演示

一键演示的顺序：北侧入口 → 中央路口 → 东侧楼前 → 南侧道路 → 西侧道路 → 返回起点。到巡检点停留两个模拟秒，转弯点不停留。

默认运动速度为每模拟秒 1 演示米，5× 播放约两分钟完成。到达中央路口并完成停留后，模拟封闭前方的楼前连接道，自动从当前位置重新规划。绿色为新路线，橙色虚线为上次路线，蓝色为已走轨迹。

页面右上角“演示指南”提供简版说明，详细讲解见 [三分钟演示稿](DEMO.md)。

## A→B 任意可通行位置规划

1. 点击页面右上方 **A→B 规划**。
2. 在地图亮绿色区域内点击 A，再点击 B。位置保持在实际点击处，**不会吸附到道路中心线**。也可以使用左侧按钮重新选择某一端，或交换 A/B。
3. 点击 **规划 A→B**，地图显示路径和 `K1、K2…` 重要途经点，右侧显示坐标、类型、累计距离与参考朝向。
4. 点击底部播放按钮，以 5× 预览到达 B 的过程；左侧可下载 **路线 + 途经点 JSON** 和 **重要途经点 CSV**。

“可通行区域”目前明确建模为：**有假设宽度的道路走廊，扣除建筑、绿化、未知地面与封闭路段，再预留机器人包络余量**。不是把所有建筑外的空地都当作已知可走。场景标注仍为人工辅助制作，并未自动辨认卫星图的地面。

默认道路宽 5 演示米、圆形机器人包络半径 0.5 演示米、栅格边长 0.5 演示米，集中配置于 `src/campus.json` 的 `navigation`。这些参数都是演示假设，不代表机器狗真实外形和道路实测宽度。

区域规划采用八邻域栅格 A*，禁止跨越障碍角；A/B 与栅格之间的连接、路径直线化以及相邻重要点连线，都用地面边界余量进行连续线段校验。栅格整格可通行的判断是保守的，狭窄位置可能因分辨率与余量被排除。贴近边界且没有可靠连接的点会提示重选，绝不偷偷移动终点或穿越未知区域。

**封路或重新选点后，旧路径、预览和导出资格立即失效**。保留 A/B 位置，需重新规划。A/B 落在封闭路段内时会报错；A、B 分属不连通区域时报告不可达；恢复道路后可以再次规划。切换回巡航任务或刷新页面会清空 A/B 模式的临时状态。

### 重要途经点怎么提取

- 始终保留 A 和 B；两点相同时合并为一个点，并同时标明起点与终点。
- 保留路线经过的已知道路路口，以及方向变化至少 25° 的转弯。
- 关键点沿完整路线的间隔最多 20 演示米，长直路会补充间隔引导点。
- 删除普通折线顶点前检查相邻关键点连线，若会穿过禁行或未知地面，就补回必要的形状保持点。因此不能保证数量一定少于直线化后的路径顶点。
- 原来的巡航模式也使用同一提取模块。巡检停留点保留，巡航道路模式的简化采用更保守的规则，不切掉任何必要弯折。

这里的“路口”来自当前人工标注的道路拓扑，尚未自动从传感器地图提取。转弯角和点间距的参数位于 `src/waypoints.ts`。完整路径始终与关键点一起导出；接实机时建议让局部导航同时使用完整路径约束，不能只把远处一个点交给它直线追踪。

## 巡航任务模式的自由探索

- **任务点**：初始状态或重置后，可以删除、上下移动巡检点。点击“在地图上添加巡检点”，再点道路，位置自动吸附。删除的预置点可恢复。编辑后必须重新生成路线。
- **起点**：点击地图工具栏的定位图标，点选开放道路。建筑、绿化及待核实区域不能选为目标。
- **返回起点**：左侧开关控制是否闭环返回。不自动优化任务顺序，按照左侧列表执行。
- **封路**：点击地图右上角禁止通行图标，点击道路或列表切换。已有任务会自动重规划；禁止封闭机器人正在走的路段。道路断开时停留原地并提示不可达，恢复后点击开始继续。
- **模拟控制**：底部开始、暂停、继续、倍速。重置恢复预置任务和道路开放状态。巡航开始后任务列表锁定，重置后可以编辑；封路仍可操作。
- **地图交互**：滚轮或按钮缩放、拖动平移、复位视角。点击道路或建筑查看简短信息。
- **图层**：切换语义 / 通行性地图；通过设置按钮显示道路网络、任务路线或参考图片。通行性图中紫色道路表示从当前位置已不可达，橙色表示人为封闭；纹理地面表示待核实。
- **图片导入**：图层设置 → 导入本地参考图片，支持 PNG/JPEG/WebP，最大 20 MB。调整透明度、位置和缩放只改变参考图，不改变路线和坐标。图片只存在于当前浏览器内存中，不上传；刷新会清空。

地图修改和封路状态不自动跨刷新保存。刷新会回到预置场景；可以下载地图 / 路线保存结果。第一版不提供任意地图文件导入或多边形编辑器。

## 地图和算法

源码分为地图数据、规划、模拟、导出和页面：

- `src/campus.json`：建筑、绿化、阴影下待核实地面、道路节点与折线、五个预置巡检点。
- `src/map.ts`：地图读取、几何工具、局部米制坐标变换。
- `src/planner.ts`：道路投影、道路中间临时节点、A*、可达性查询。路径代价为折线长度，道路默认双向。
- `src/freeSpace.ts` / `src/abNavigation.ts`：区域通行判定、保守栅格、A→B A*、路径直线化、A/B 导出。
- `src/waypoints.ts`：按起终点、路口、转弯、最大间距和通行校验提取重要途经点。
- `src/ABWorkspace.tsx`：独立的 A→B 点选、结果展示和模拟预览界面。
- `src/simulation.ts`：巡航与停留、暂停继续、人工封路、自动演示、不可达与恢复。沿道路折线积分推进，不直连任务点，不做切角平滑。
- `src/export.ts`：地图 JSON、路线 JSON、途经点 CSV。
- `src/MapView.tsx` / `src/App.tsx`：SVG 图层、交互与任务台。

默认场景坐标范围为 1000 × 920 图形单位。1 图形单位假设为 0.25 演示米，因此场景为 **250 × 230 演示米**。路宽和建筑轮廓也只是示意，不能据此判断实机净空或碰撞安全。

图形内部原点在左上角，Y 向下。导出使用统一的 `demo_map`：原点在左下角，X 向右、Y 向上：

```text
x_export = x_svg × 0.25
y_export = (920 - y_svg) × 0.25
```

X/Y 没有绑定地理东/北，未提供经纬度或 RTK 对齐结果。可辨认道路从阴影中经过时继续保持道路连接；“阴影”本身不作为禁行类别。

## 导出文件

所有文件包含或注明 `frame_id: demo_map`、`scale_is_mock: true`。JSON 另包含版本号和 `georeferenced: false`。

| 文件                   | 内容                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| `campus-map.json`      | 区域轮廓、语义、通行状态、道路网络、预置巡检点、当前封闭道路                                           |
| `patrol-route.json`    | 完整任务列表与顺序、当前规划的完整折线、剩余任务顺序、已完成任务、已走轨迹、起点与是否返回、关键途经点 |
| `ab-route.json`        | 精确保留的 A/B、完整路径、重要途经点、提取规则、区域规划参数、封路状态                                 |
| `ab-waypoints.csv`     | 重要点坐标、参考朝向、累计距离与入选原因 `reasons`                                                     |
| `patrol-waypoints.csv` | 当前规划的关键途经点，含序号、坐标系、演示标记、X/Y、参考 yaw、经过/巡检/返回类型、名称和停留秒数      |

A/B 导出显式带有 `executable_on_robot: false`、`field_verified: false`，不输出假经纬度。`path` 是完整路线，`waypoints` 是重要途经点；每个点的 `reasons` 可包含 `start`、`goal`、`turn`、`junction`、`spacing`、`geometry`、`inspect`、`return`。累计距离沿完整路线计算，参考朝向也取完整路线的切线方向。

`yaw` 为弧度，相对导出坐标的 +X 方向，逆时针为正；巡检点使用离开该点的路线方向，最终点沿用到达方向。它是路线几何参考方向，不是真实机器狗姿态。

**重规划后的 `path` 和 CSV 表示最近一次生成的有效路线，起于重规划位置。** 已经走过的部分保存在 `traveled_path`；`task_order` 保留整个任务顺序，`remaining_task_order` 表示最近一次规划时仍未完成的巡检点。导出还包含实时的 `completed_task_ids`。任务编辑后、不可达时，路线导出禁用。

地图 JSON 的区域和道路是矢量表示，不是 ROS 栅格地图或可直接用于实机的导航指令。此版道路沿人工推定的网络连通，不推导未知地面的可通行性。

## 验证

```bash
npm test
npm run build
```

默认 `npm run test:e2e` 使用本机 Firefox。浏览器验收（先保持 `npm run dev` 在运行）：

```bash
npm run test:e2e:firefox
```

它通过标准 WebDriver 控制本机 Firefox，验证两种桌面分辨率、图层、断路与恢复、暂停继续、点选与缩放、图片对齐、一键演示完成、A/B 原始坐标保留、禁行位置拒绝、区域断路与恢复、关键点展示和实际文件下载。截图、下载位于 `test-results/`。

默认使用 Ubuntu Snap Firefox 自带的二进制。其他安装方式可指定：

```bash
FIREFOX_BINARY=/path/to/firefox GECKODRIVER_BINARY=/path/to/geckodriver npm run test:e2e:firefox
```

另附 Playwright / Chromium 测试，可通过以下命令运行：

```bash
npx playwright install chromium
npm run test:e2e:chromium
```

## 后续接真实机器狗

按以下接口顺序推进，现有界面和任务逻辑可以保留：

1. 用现场控制点校准地图尺度和几何位置，确认真实道路、围墙、门禁、台阶和净空。
2. 与同门确认 RTK 参考坐标框架、位置格式、更新频率和朝向来源；建立地理坐标与机器人 `map` 坐标的变换。
3. 约定接收路线还是逐个导航点、到点容差、巡检停留、执行成功/失败反馈。全局路径需能被局部导航使用，而不是仅给建筑另一侧的一个远点。
4. 将模拟位置来源替换为机器人定位，将模拟到点事件替换为实际执行反馈；验证局部感知、绕障与停车能力。
5. 逐步用激光 / 视觉语义建图替换当前人工地图，保持任务、规划与展示模块分离。

地图误差、真实坐标对齐、感知闭环及更可泛化的自动建图路线，详见 [从示意地图到真实机器狗导航](MAPPING_ROADMAP.md)。
