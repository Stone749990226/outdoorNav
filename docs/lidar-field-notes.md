# 前雷达实测与高度带（2026-10-30 室外）

只读采集三帧 `/airy_201/points`（站立静止，未移动），换算到车体坐标系 base_link 后统计。
工具：`tools/lidar_snapshot.py`（只订阅点云和静态外参，不发速度、不读 RTK）。

## 结论

| 项目 | 实测 |
| --- | --- |
| 地面在车体系的高度 | z ≈ **−0.42 m**（三帧一致，1% 分位 −0.421） |
| 雷达离地高度 | 约 **0.42 m**（同上推算） |
| 每帧点数 | 约 43600 |
| 水平可视方向 | **只看得到车头半圈**：约 270°→0°→90°；90°～270°（后半球）**一个点都没有** |
| 后半球可用距离 | 无数据；最远可见在 270～300° 方向约 14.7 m（现场右侧开阔） |

高度带是相对 **base_link**（车体），不是相对地面；两者的换算差就是上面测到的 0.42 m。

## 当前配置与含义

现场配置 `deploy/lynx/robot.fieldtest.json`：

- `cloud_min_height_m = -0.3`、`cloud_max_height_m = 0.3`；
- 换算到地面以上约 **0.12～0.72 m**，即检测约 0.1～0.7 m 高的物体；**0.7 m 以上按约定不检测**；
- 地面（−0.42）落在带外，不会被当成障碍；
- `scan_range_min_m = 0.5` 是全向近距过滤，作为粗筛保留。

## 自车回波

- 0.5 m 内每帧只有约 105～259 点，量级上即可视为自车部件；这层已被 `scan_range_min_m` 滤掉。
- 0.5～1.6 m 内的几千点**更可能是真实场景**（当时车旁有建筑、地面边缘），不能当成自车直接删掉。
- 只有前雷达参与，**没有和后雷达融合**；后雷达（另一台接收机）未接入。
- 因此倒车、横移都不可用（速度桥本身也禁止倒车与横移），只适合沿路向前行驶。

## 下一步：走动采集 + 车体体素过滤

站立数据无法证明“走路时腿伸到多远”，需要在空旷处低速直走十几秒采点云，做法：

1. 逐帧把点换算到 base_link；
2. 统计每个体素的出现频率：**跟着车一起动、几乎每帧都在同一位置的体素＝自车**（世界物体在车体坐标里会相对后退）；
3. 只剔除这些体素，得到 3D 车体包围区；
4. **不要用“距离范围一刀切”**——那会把真实近处障碍一起去掉；
5. 验证：车旁约 1 m 放一个 0.3 m 高的箱子，确认仍在障碍图里；同时确认腿回波消失。

在此之前，0.5 m 粗筛 + 高度带是现有的保守处理，不宣称自车回波已解决。
