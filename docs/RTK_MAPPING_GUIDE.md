# RTK 采集与园区底图生成指南

目标：沿实际道路采集 RTK 轨迹，生成有真实尺度的道路底图，供网页选点、路径规划和 ROS2/Nav2 使用。

核心原则：**先用实测数据建立米制道路，再绘制网页和背景。** 道路形状、长度以可靠实测数据为依据；中心轨迹不能直接代表道路宽度和全部可通行空间。

## 1. 出门前：给道路和路口编号

以路口、入口和道路终点划分路段。弯道可以保留在同一段内，用多个轨迹点表达。

| 道路编号 | 起点编号 | 终点编号 | 说明 |
| --- | --- | --- | --- |
| R01 | J01 | J02 | 北侧入口到中央路口 |
| R02 | J02 | J03 | 中央路口到东侧入口 |
| R03 | J03 | J01 | 返回北侧入口的另一条路 |

以上是编号示例，不代表当前园区已确认这些连接。

- 在草图上标出编号；同一公共路口始终使用同一个编号。
- 为每个端点选一个明确地面位置，例如路面标记，并拍照说明天线放在哪里。
- 一个路口区域较大时，还要记录各道路的接入位置，不能把整个路口都压成一个导航点。
- 首次只采一个小区域，包含弯道、公共路口和支路，验证流程后再扩展。

## 2. 现场：使用 u-center 录制

接收器继续通过 USB 连接 Windows，录制阶段不需要 ROS2。

1. 在 u-center 连接正确的 COM 口，确认位置持续更新、差分改正数据正常。
2. 查看定位状态。主要采图数据应为 **RTK FIX / 固定解**；GGA 中对应质量值 `4`。浮点解和普通差分解要保留记录，但不能直接当作可靠测图结果。
3. 确认日志能保存位置、时间和质量信息。建议保存 NMEA GGA、RMC，以及 UBX NAV-PVT；原始日志保留为 `.ubx`。
4. 使用 u-center 的日志录制功能开始记录，通常位于 `Player → Record` 或录制按钮；具体名称随版本变化。先试录一小段，停止后确认文件存在且有数据。
5. 天线置于起点地面标记的对应位置，保持稳定固定解，建议停留约 20～30 秒。记录停留开始和结束时间。
6. 沿道路中心正常步行，尽量保持天线位于中心线上。弯道按实际弧线走；绕车、离开中心线、信号退化时记下时间和原因。
7. 到终点标记处，保持同样的天线放置方式，再停留约 20～30 秒，记录时间，停止录制。
8. 用新的日志沿原路返回，重复采集，用于比较往返轨迹。

建议每条日志只录一个路段，例如 `R01_forward_20260928.ubx` 和 `R01_reverse_20260928.ubx`。若连续录多段，必须记录经过各路口的时间，以便后续切段。

停留时间是操作建议，不是精度保证。固定解持续不稳定时应标记待补采；不要为了补齐道路而采用明显漂移的数据。

## 3. 每条日志附一份采集记录

下面的时间仅为填写示例，使用接收机显示的 UTC 时间，并记录日期。北京时间为 UTC+8；跨午夜时注意日期变化。

| 项目 | 示例 |
| --- | --- |
| 园区 / 道路 | campus_a / R01 |
| 日志文件 | R01_forward_20260928.ubx |
| 起点 / 终点 | J01 / J02 |
| 采集方向与类型 | 正向，中心线 |
| 起点停留时间 UTC | 2026-09-28 02:00:00～02:00:25 |
| 终点停留时间 UTC | 2026-09-28 02:02:00～02:02:25 |
| 异常区间 UTC | 02:01:10～02:01:18，绕过车辆 |
| 道路情况 | 窄处净宽待测；右侧有路沿 |
| 配套照片 | J01.jpg、J02.jpg |

同时保存接收器、差分服务或基站来源、坐标参考框架和天线放置方式。同一园区各次采集应保持一致；更换基站或配置后要复核位置是否发生偏移。

记录可先用表格保存，不需要现场手写 JSON。建议整理为：

```text
survey/campus_a/
  raw/             原始 UBX 日志
  photos/          路口、边界和异常照片
  segments.csv     日志与道路、端点、时间的对应关系
  nodes.csv        公共路口编号与地面标记说明
  checks.csv       不参与建图的检查记录
  output/          清洗轨迹、道路网络和生成的地图
```

## 4. 日志如何生成道路底图

当前已有针对闭环与已确认支路的建图脚本，通用多园区、多路段采集记录导入仍待扩展。

| 步骤 | 处理内容 | 得到什么 |
| --- | --- | --- |
| 解析 | 校验报文，提取完整时间、经纬度、解状态、精度估计 | 带质量信息的轨迹 |
| 清洗 | 检查重复和乱序；按质量、速度和局部一致性识别异常 | 可用段、异常段及原因 |
| 坐标转换 | 同一园区选定固定原点，统一转换到局部米制坐标 | `map` 中的 x/y，单位米 |
| 道路重建 | 排除端点停留和绕行区间；适度平滑、简化，保留弧线 | 每条道路的实测点列 |
| 路口拼接 | 核对连接关系，在接入位置切分主路，统一公共节点 | 支持中段分叉的路网 |
| 网页绘制 | 将米制道路转换成 SVG 显示坐标 | 可缩放的道路底图 |

所有道路使用同一个坐标原点，不能每段各自设原点再直接拼接。米制坐标建议采用 X 向东、Y 向北；SVG 的 Y 向下，由显示变换处理。缩放网页不改变真实道路长度。

滤波要保留真实转弯，并保存原始数据和删除原因。质量退化造成的缺口标为待补采，不能直接连线并认定可通行。

拼接依靠公共路口编号和现场确认，不要求两份日志起终点重合。支路可以接入另一条轨迹中段：在确认的接入位置插入公共节点并切分主路，再连接支路。端点偏差小且质量可靠时可局部修正；偏差大时复核或补采。不能仅因位置接近就合并，也不能强行拉伸整条道路来闭环。

## 5. 添加背景与可通行边界

道路绘制完成后，再叠加卫星截图、建筑、绿地和名称。

当前网页已加入[北区园区示意底图](../outdoor-patrol-demo/src/assets/north-building-basemap.svg)，参考高德地图和卫星图表现中央 30 层主楼、东侧裙楼与周边绿化。底图按当前实测路网的显示坐标布置，楼影采用淡色投影；建筑位置和道路宽度为外观示意，未经地标精确配准，不作为通行边界。巡航页的图层设置和 A→B 页的地图按钮均可关闭底图。

- 底图通过多个分布均匀的明确地标配准；留其他地标检查对齐误差。
- 高德常用 GCJ-02，RTK 坐标参考框架需确认，两者不能直接混用。
- 建筑外观、文字等可以只作显示背景；影响规划的墙、路沿、禁行区需要可靠测量或现场核实。
- 中心轨迹不能推导道路净宽。窄路、弯道、路口需要补测边界或净宽，未测部分保留未知状态。

最终应保留结构化道路坐标和连接关系。PNG 等图片用于查看；Nav2 占据栅格还需要明确的分辨率、原点和通行边界，不能直接把截图当作导航地图。

## 6. 检查底图，再接入规划

生成后至少检查：

- 往返轨迹是否一致，弯道是否被错误拉直，缺测区间是否仍有标记。
- 公共路口是否正确连接，断头路是否保留；真实闭环回到原标记时有多大偏差。
- 用未参与拟合和重建的检查点或另一次采集检查位置，记录误差、定位质量及薄弱路段。重复一致也不能单独证明绝对精度。
- 道路边界、障碍和净宽是否足以支持计划使用的机器人。

网页点击 A/B 后，将点击位置转换到米制坐标，检查是否可达，再沿实测路网规划，导出完整路径、关键点、朝向和地图版本。经纬度可附带，但称为“推算目标坐标”。

完整米制路径可发送给 Nav2 `FollowPath`；实机还需要与地图一致的机器人定位、朝向、局部避障和运动控制。底图生成成功不等于实机导航已具备条件。
