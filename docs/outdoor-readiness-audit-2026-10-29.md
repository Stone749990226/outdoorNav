# 出门前的限制审查与现场档调整

目标：不在室外临时发现隐含门槛、改逻辑再重启。此次修改代码和离线测试；没有启动真实 RTK、操作底盘或部署机载生产服务。

## 找到并修复的实际问题

| 问题 | 修改后 |
| --- | --- |
| 固定／浮点一切换就重置稳定计时，固定任务又拒绝浮点，反复停机 | 合格切换保持稳定计时；现场档启动稳定窗口从 5 秒改为 2 秒，并允许合格浮点继续。无效解、单点解、断流仍不放行 |
| 停车要求速度低于 0.01 m/s，正常定位噪声可能让系统一直认定没停 | 现场档放到 0.03 m/s、0.03 rad/s，仍要求一秒连续近零和新鲜实测反馈 |
| 配置说 3 m 到达，任务却等最后一段和控制器的 0.5 m 完成 | 任务按目标距离和有序路线剩余距离判断到达，再取消／释放控制器并确认停车；不再隐藏地强求 0.5 m。U 形路不能隔着弯直接算到达 |
| 命名地点自动附带最终朝向，用户只想走到点也得对准 | 现场档不附带命名地点的最终朝向；请求中明确写入 yaw 时仍遵守 |
| 规划连败三次就结束，可能不足几秒，行人离开前已判失败 | 现场档改为最多 60 秒停车等待和重规划；恢复后继续。控制器无进展也给 60 秒，不无限卡死 |
| 四次不连续的位置异常也会累计锁死 | 接受一个正常位置后清零异常连续计数；连续异常仍锁止 |
| IMU 断流恢复时重新锚定没有扣掉已累积的转角，可能多加一次转角 | 重新锚定保留局部坐标连续性，按当前绝对朝向减已有局部角计算，不再叠加旧转角 |
| 速度不到固定 0.25 m/s 就永远不修正航向 | 现场档最低 0.12 m/s，同时速度必须超过接收机速度误差估计的三倍；明显转弯时不用航迹强行改航向 |
| 膨胀范围和衰减写死在生成器 | 变成配置；机体半径仍 0.6 m，额外影响带 0.2→0.1 m，衰减系数 3→5（越大越快降低软代价）。没有缩小机器人碰撞轮廓 |
| 底盘趴着／使用模式错误时也接任务，之后才发现有指令没运动 | 速度桥只读回查状态，提前在网页报告未进入导航模式；桥自身也拦截姿态、步态或使用模式未确认的运动。不会自动起立 |
| 生产入口假设前雷达驱动已经启动 | 端口空闲时启动唯一前雷达接收器；已有接收器则复用，最终仍由真实扫描是否更新判断。先预检所有权，再创建速度桥 |
| 路线途经点的透明点击区拦截选点，替换目标时悄悄保留旧终点 | 途经点点击不再吞掉地图选点事件，保留说明和键盘访问；扩展浏览器回归核对实际下发坐标，避免沿用旧目标 |
| 每次重启都要手工 activation，或 ready=true 却显示未标定阻塞 | 演示档服务自动激活，但所有真实健康门仍生效；未验收的演示航向、过大盲区独立列作“现场策略提示”，不混进阻塞原因 |

空旷 `+inf` 扫描、无回波清除旧障碍、缺位置先停车后限时恢复等上一轮修复均保留。

## 现场档关键参数

以下在 `deploy/lynx/robot.fieldtest.json`；默认严格档不自动放宽：

| 参数 | 现场值 | 含义 |
| --- | --- | --- |
| `gnss_stable_s` | 2 | 初始或真正断流后的连续稳定时间，严格默认仍为 5 秒 |
| `allow_float_during_fixed_task` | true | 合格浮点可以继续固定档起步的任务 |
| `gnss_speed_accuracy_mps` | 0.15 | 速度误差估计门槛；缺失／零值不当成可靠零速 |
| `stopped_linear_mps` / `stopped_angular_rps` | 0.03 / 0.03 | 近零速度判定，保持一秒 |
| `navigation_recovery_timeout_s` | 15 | 定位短暂不可用时先停，最多等 15 秒恢复 |
| `planner_patience_s` / `controller_patience_s` | 60 / 60 | 暂时无路／无进展的等待预算 |
| `inflation_padding_m` | 0.1 | 机体半径外的软影响带；总配置范围为 0.7 m |
| `inflation_cost_scaling` | 5 | 影响带软代价的下降速度，不是致命碰撞范围 |
| `planner_tolerance_m` | 0.3 | 路径规划目标附近的搜索容差 |
| `transform_tolerance_s` | 0.3 | 坐标变换时间容忍度 |
| `respect_place_heading` | false | 命名地点不强求最后对准角度 |
| `auto_activate` | true | 服务启动后无需再手工 POST 激活 |
| `require_chassis_ready` | true | 真狗必须已站立、处于正确步态和导航使用模式 |

模拟档不要求真实底盘状态，速度只到隔离虚拟话题。

## 膨胀可热调整，不用改逻辑重启

在运行导航的同一 ROS 环境中，下列是已有 Nav2 参数服务的热调整命令（不改变机体半径）：

```bash
ros2 param set /global_costmap/global_costmap inflation_layer.inflation_radius 0.7
ros2 param set /local_costmap/local_costmap inflation_layer.inflation_radius 0.7
ros2 param set /global_costmap/global_costmap inflation_layer.cost_scaling_factor 5.0
ros2 param set /local_costmap/local_costmap inflation_layer.cost_scaling_factor 5.0
```

每条命令都应检查返回成功；修改 `robot.fieldtest.json` 可持久保存到下一次启动。
并非所有配置都有热重载：扫描高度、盲区及任务策略目前仍在启动时加载，不能声称改 JSON 即刻生效。

## 仍没有用猜测“修掉”的一项：自车回波

**旧的 3 m 最小距离不是合格的自车过滤，会让近处真实障碍一起消失。** 按用户要求，现场与模拟档均改为 `scan_range_min_m=0.5`；取消半米外的大范围屏蔽。半米内目前仍是全角度过滤，不是腿部角度／几何过滤的完成证明。
现有报告没有足够的原始走动点云来区分腿、地面回波、安装坐标错误或真实物体，不能仅凭“放到 3 m 后能走”就证明腿伸到了那里。

提供不涉及 RTK、不发速度的五秒留样工具，复用已运行的前雷达和静态安装变换；2026-10-30 室外实测结果与高度带换算见 [前雷达实测](lidar-field-notes.md)：

```bash
# 在已经 source ROS、rslidar 工作空间且仓库在 PYTHONPATH 的环境中执行。
python3 tools/lidar_snapshot.py --output /tmp/lidar-snapshot-unique-name
```

输出三帧传感器／车体坐标点及近距分布，目录已存在时拒绝覆盖。真实走动腿回波的几何过滤仍需用对应姿态的数据确认；没有这一步，不能保证所有现场误障碍都已消除。

## 启动次序

终端 A（长驻）：`bash deploy/lynx/fieldtest/start_production.sh`。

终端 B：现场已清空、且明确允许起立时，执行 `bash deploy/lynx/fieldtest/activate_robot.sh`。
这条命令会起立并核对姿态、步态、导航使用模式；失败就停止，不把“命令已发出”当作完成。
仅启动生产服务不会偷偷起立或恢复旧任务。

## 验证口径

- 离线参数／状态回归覆盖固定浮点切换、异常点连续计数、恢复后的朝向、受阻计时和演示档限制。
- 本地 Docker 真实网页、HTTP、Nav2＋虚拟 RTK/IMU 闭环：普通策略验证到达、取消、替换、航向断流停车与恢复。
- 现场三米档单独验证临时障碍停车等待、障碍消失清除后继续，以及在三米范围内停车，而不是只跑严格 0.5 m 档冒充现场配置。
- 所有模拟运动都只在域 94、localhost 的 `/isolated_task_flow/cmd_vel`；不连接真狗、不发布真实运动指令。
- 不把模拟成功等同于真实自车过滤／行人绕行已验收，也不保证卫星、磁场或机械状态在室外不会出现新问题。
