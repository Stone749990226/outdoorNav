## 当日保留的现场改动

### 分割和楼梯观测

- SegFormer-B0 / ADE20K：类别 53 映射 `stairs`；CUDA 推理；分数低于 0.55 的像素标为未知。
- 置信度仍在模型内部用于过滤，但不再发布单独的浮点图，也不再作为楼梯节点的同步输入。标签、深度和内参仍需配对。
- 相机由 1280×720 降为 640×480；现场观测频率受整机处理与传输影响，不能用单次模型推理耗时代表整条感知链速率。
- 时间配对容差从 0.05 s 改为 0.30 s；现场曾将 TF 改为最近可用值；整理时已合入远端 `f3cc000` 的有界队列、非阻塞采样时刻 TF 配对修复，撤掉该临时取法。注册深度要求零畸变，彩色图保留原畸变。这几项是现场试验改动，尚未证明运动时的像素和时间对齐准确。
- 后处理统一使用整片楼梯点云的三维 PCA：从斜面法向求水平上升方向。无需最底部台阶；不再使用“前缘失败后再用主轴”的两套分支，也不假设最长轴一定横跨楼梯。退化点云、竖直墙、水平面或向下方向不生成上楼朝向。

### 步态和控制

- 普通导航保持开启，周期方向引导关闭；field 开启 `terrain.enabled` 和 `can_climb_stairs`，平地/楼梯命令码为 12290 / 12291。实时状态机拥有步态，不依据录制地图区段切换。
- 当前视觉空间范围为 2 m；最近**可见楼梯点**进入 1.2 m 后禁止平地逼近，朝向有效时可立即进入对准，再停车确认、请求楼梯步态、等待底盘反馈后前进。这不是脚到第一台阶距离的可靠测量，近距离遮挡/漏检仍有风险。
- 爬升中 IMU 倾斜时可保持楼梯阶段，即使短暂没有视觉观测；仍要求有效 IMU、新鲜匹配的楼梯步态反馈及原有导航健康条件。IMU 水平并有连续有效“无楼梯”观测才恢复平地；缺消息不是“确认无楼梯”。

### 启停修复

部分包创建独立进程组，外层进程组退出不保证它们退出；停栈 CLI、boot 和 watchdog 也可能同时收尾。

- boot 在清日志/写状态前获取部署锁，已有 boot、正在清理或遗留 state 时立即报错，不覆盖旧证据。
- 清理过程互斥；每个组件的生命周期收尾有 5 s 预算。Linux 额外按精确 `RBNX_BOOT_ID` 和 PID 启动身份清理分离子进程，TERM 后再 KILL；不按名称批量杀进程。
- 未收干净时保留 state，成功返回前等待原 boot 释放启动锁。不要再手动删除 state 绕过检查。
- 这次验证为 Atlas-only，不代表已经跑过完整硬件栈的多次重启压力测试。

2. **对准与模式退出。** 现场出现过 `align → restore_flat → flat → align`。检查是否未进入 climb 就因“水平+暂时无楼梯”触发退出，以及对准时视野丢失如何处理。不能仅凭日志猜成惯性或法向翻转。
3. **旋转命令的全链路。** 同时记录目标 yaw、实测 yaw、状态机角速度、最终速度和安全闸阻止原因。区分“没生成转动”“被闸拦”“底盘没执行”“执行后过冲”。0.25 m 半径不是已标定安全结论。
4. **近距离平地误上台阶。** 实测标注距离与最近可见点距离的差别，确认切换前确实停住，且真实步态反馈已是 12291；先不连续自动重试。
5. **控制器切换。** 现有执行器已有释放旧 FollowPath 再提交新 controller 的路径；没有证据证明“切 controller 本身取消任务”。此前一轮明确终止原因是 lidar 恢复等待超时，勿照未经验证的归因继续打补丁。
6. **避障复现。** 保留车心判据，使用非人体障碍物，检查是否能稳定复现“绕到一半过早回正”。未实测的人体前方 0.5 m 回波不能当作“已证明看到了人”。
