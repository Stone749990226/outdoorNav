# 实测轨迹与场景

原始记录保留在仓库根目录，正式环线与支路输入为 `1.ubx`、`2.ubx`。不要修改原始文件。

```bash
./nav survey --loop 1.ubx --branch 2.ubx
./nav scene build
./nav up
```

运行仿真前再生成数据。重新生成后，入口会检查指纹并重建前端与 ROS 包。

## 处理链

`receiver.py` 校验并解析混合 NMEA/UBX 日志，读取 GGA 定位及 NAV-PVT 质量信息。`coordinates.py` 使用共同 WGS84 原点转换为局部 ENU：X 向东、Y 向北。

`survey.py` 依次处理时间顺序与跨午夜、异常点、缺测分段、静止段压缩、转角保护平滑、0.5 米重采样、0.15 米简化、闭环和支路连接修正。默认参数集中在 `PARAMETERS`，沿用基线算法；出现不能确认连续的缺测路段时拒绝生成连接。

`scenes/north_campus/origin.json` 固定共同原点。`survey/` 保存原始轨迹、滤波轨迹、米制路网和报告。报告记录输入哈希、质量分布、处理参数及连接修正。

本批正式记录的 GGA 质量为 **DGPS（2）**，不能据此宣称厘米级 RTK fixed 或已验证的绝对位置精度。

## 场景包

`layout.json` 定义示意建筑、假设道路宽度和场景参数。`generated/bundle.json` 是 Web 与 ROS 共用的入口，包含：

- schema、路线和场景版本，坐标原点；
- 米制路网、原始/滤波轨迹及处理报告；
- 建筑碰撞轮廓、永久可通行面、栅格参数和出生位姿；
- Gazebo 世界、模型、导航地图与资源哈希。

加载时检查格式与资源哈希。Web 只在显示时把米制坐标转换为 SVG 坐标；不会向多个源码目录复制路线 JSON。

示意建筑的尺寸、道路宽度和高度属于仿真假设。未来雷达/深度相机重建需要额外解决采集标定、SLAM、地图配准、网格与碰撞模型简化，不能直接把实测中心线当作真实三维地图。

## 诊断与证据

`./nav capture` 在当前运行目录的 `captures/<id>/probe/` 中，按编号保存栅格、点云、TF、仿真与墙钟时间；点云使用其采集时刻的 TF，缺失会明确记录。点数截断记录原始数量和步长。

`./nav diagnose` 提供残留格、来源归因、清除历史、几何关系、未知区膨胀和快照差异报告。各实验保留原有统计口径；OccupancyGrid 的 99/100 与原始 costmap 的 254 含义不同。

`artifacts/baseline/` 为重构基线；`artifacts/history/` 保存旧实验产物，默认不纳入版本控制；新运行保存在 `artifacts/runs/`。
